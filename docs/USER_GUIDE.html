讓個人筆電與工作站顯卡，安全、可靠地共享本機 AI 算力

LocalGPU-OS 是一個與 AI 模型及應用程式無關的本機運算資源仲裁層。 它把硬體探測、顯存排程、溫控節流與隔離 Worker 執行拆分成乾淨的四層架構， 讓你用 8GB 筆電獨顯（如 RTX 4060 Laptop）也能安心跑離線 PDF／OCR 與未來的 AI 工作負載， 零雲端 API 費、無訂閱綁定、不因資源撞車而當機。

✨ 五大核心優勢

🔒 三層 VRAM-Gate，拒絕顯存超賣

採用 VRAM_admission = max(0, VRAM_free,observed - VRAM_safety - VRAM_pending) 即時觀測裝置可用顯存，同時感知外部程序（如遊戲、Ollama）與受控 Worker，避免重複扣除，也不讓兩個 GPU 任務互相踩死。

✅ 真實 Backend 驗證，絕不假裝跑 GPU

不只看參數寫了 cuda，而是實際檢查 ONNX Runtime det / cls / rec Session 的 get_providers()，確保真的啟用 CUDAExecutionProvider，否則誠實回報降級或 Fail-Closed 拒絕。

🧩 零依賴 Core OS ＋ 隔離 Worker .venv

Core OS 只使用 Python 標準函式庫，嚴禁安裝 PyTorch / TensorFlow；每個 Worker 擁有獨立 workers/<id>/.venv，啟動時直接解析精準路徑，完全不依賴系統 PATH，全倉 0 處 shell=True。

🌡️ 溫控四態守衛 ＋ 安全 CPU 降級

內建 NORMAL / COOLING / CRITICAL / SENSOR_DEGRADED 狀態機。當顯存不足或溫度偏高時， 開啟 --allow-cpu-fallback 會自動改申請純 CPU_COMPUTE + SYSTEM_MEMORY 租約（不佔 GPU Lease）完成任務。

🛡️ 載入前 SHA-256 校驗 ＋ 原子化輸出

離線執行期（RUNTIME_OFFLINE）零聯網下載，載入模型前強制核對 64 位 SHA-256； 輸出先寫入 .staging 驗證完整後再 os.replace，取消、OOM 或強殺絕不留下半成品，也不破壞舊結果。

♻️ 7 步驟取消協議 ＋ 孤兒程序防誤回收

支援跨平台原子取消檔與寬限期優雅退出；逾時強制終止後必重採樣 VRAM 確認硬體狀態。 即使 Core OS 意外崩潰重啟，也會交叉比對 PID 與建立時間，絕不誤回收仍在運作的 Worker 租約。

🚀 五分鐘快速上手（Windows 11 PowerShell）

環境需求：Python 3.10+（Core OS）；若要安裝 ocr_pdf 隔離 Worker，建議使用 Python 3.12（Windows 11 + NVIDIA RTX 4060 Laptop 已實機完整驗證）。
1

取得專案並執行硬體健檢（M1-A）

不需要安裝任何第三方套件，立刻確認本機 GPU 型號、可用顯存、溫度與動態策略分級。

PowerShell 
git clone https://github.com/etrnya/LocalGPU-OS.git
cd LocalGPU-OS

$env:PYTHONPATH="src"
python -m localgpu_os.presentation.cli doctor
python -m localgpu_os.presentation.cli doctor --json
2

查看即時 VRAM-Gate 仲裁與租約狀態（M1-B）

確認目前 VRAM_admission（可入場顯存）、VRAM_pending 與活躍租約數量。

PowerShell 
$env:PYTHONPATH="src"
python -m localgpu_os.presentation.cli status
3

建立隔離的 ocr_pdf Worker 環境（僅需安裝一次）

所有 PDF、RapidOCR 與 CUDA 13 / cuDNN 9 Runtime wheel 皆完全隔離在 workers\ocr_pdf\.venv，不污染系統與 Core OS。

PowerShell (INSTALL_PHASE) 
# 1. 建立 Worker 專屬虛擬環境
py -3.12 -m venv workers\ocr_pdf\.venv

# 2. 安裝鎖定版本套件（含 PyMuPDF、RapidOCR、ONNX Runtime GPU 與 NVIDIA CUDA/cuDNN wheel）
workers\ocr_pdf\.venv\Scripts\python.exe -m pip install --only-binary=:all: -r workers\ocr_pdf\requirements.txt

# 3. 連結 LocalGPU-OS SDK 路徑
Set-Content -Path "workers\ocr_pdf\.venv\Lib\site-packages\localgpu_os.pth" `
  -Value "$((Get-Location).Path)\src" -Encoding UTF8
4

準備輸入清單 input_manifest.json

依安全契約，檔案清單禁止內嵌 Base64，且所有檔案路徑必須落在 --allowed-root 目錄內（自動攔截 .. 與 Symlink 逃逸）。

inputs/manifest.json 
{
  "files": [
    { "path": "report_native.pdf", "role": "input" },
    { "path": "scanned_coa.pdf", "role": "input" },
    { "path": "label_photo.png", "role": "input" }
  ]
}
5

執行離線文件處理（RUNTIME_OFFLINE）

原生 PDF 會自動跳過 OCR 直接用 PyMuPDF 抽取；掃描 PDF 與圖片自動走 RTX CUDA OCR；若顯存不足可加上 --allow-cpu-fallback 安全降級至 CPU。

PowerShell 
$env:PYTHONPATH="src"
python -m localgpu_os.presentation.cli run ocr_pdf `
  --input-manifest .\inputs\manifest.json `
  --allowed-root .\inputs `
  --allow-cpu-fallback `
  --json `
  -- --output-dir .\output --job-id job_001

🐍 Python SDK 整合範例

你可以直接在自己的 Python 腳本（如知識庫匯入、報表批次解析）中透過 LocalGpuClient 呼叫，並支援透過 threading.Event 隨時優雅取消任務。

Python 
from pathlib import Path
import threading
from localgpu_os import LocalGpuClient

client = LocalGpuClient(workers_dir=Path("workers"))

# 1. 先檢查硬體狀態
report = client.doctor()
print("GPU:", report.profile.device_name, "| Admission VRAM:", report.decision.vram_admission_mib, "MiB")

# 2. 執行離線 OCR / PDF Worker（支援取消事件與自動 CPU 降級）
cancel_event = threading.Event()
result = client.run_worker(
    worker_id="ocr_pdf",
    input_manifest={"files": [{"path": "sample.pdf"}]},
    allowed_root=Path("./inputs"),
    extra_args=["--output-dir", "./output", "--job-id", "sdk_job_001"],
    allow_cpu_fallback=True,
    cancel_event=cancel_event,
)

if result.succeeded:
    print("完成！輸出結果：", result.output_data["jobs"][0]["outputs"])
else:
    print("狀態：", result.status, "| 錯誤碼：", [e.value for e in result.error_codes])

🛠️ 常見錯誤碼與排錯速查

錯誤碼 / 狀態 觸發原因 建議處理方式
VRAM_INSUFFICIENT 即時 VRAM_admission 低於任務需求（如 ocr_pdf 需 2048 MiB + 安全餘裕 1536 MiB）。 關閉佔用顯存的外部程式，或加上 --allow-cpu-fallback 改用純 CPU 安全完成。
WORKER_ENV_NOT_INSTALLED 找不到 workers/<id>/.venv/Scripts/python.exe（絕不偷用系統 PATH）。 依照「Step 3」建立該 Worker 的隔離 .venv 並安裝 requirements.txt。
WORKER_MANIFEST_INVALID Manifest 格式錯誤、內嵌 Base64、檔案超過大小上限、或路徑企圖逃逸 --allowed-root（含 Symlink）。 確認輸入檔案皆位於 --allowed-root 內且使用檔案路徑參考而非 Base64。
THERMAL_COOLING_WAIT GPU 溫度超過警戒值（預設 82°C），進入 COOLING 節流狀態。 等待顯卡降溫至恢復門檻（72°C）以下，或使用 --allow-cpu-fallback 改跑 CPU。
THERMAL_CRITICAL_ABORT GPU 溫度超過緊急門檻（預設 88°C），強制停止核發 GPU 任務。 檢查散熱與風扇設定，待降溫並穩定超過冷卻遲滯時間（60s）後再執行。
THERMAL_SENSOR_DEGRADED 無法讀取溫度感測器或硬體快照過期，系統進入保守 Fail-Closed 模式。 執行 lgpu doctor 確認驅動與 nvidia-smi 狀態；純 CPU 任務仍可執行。
DISK_SPACE_INSUFFICIENT 工作目錄或暫存區剩餘磁碟空間低於 Worker 最低需求（預設 256 MiB）。 清理磁碟空間，或使用 --work-dir 指定空間充足的磁碟區。
LEASE_RECLAIM_BLOCKED 舊任務心跳逾時但 OS 交叉驗證程序仍存活（或無法確認已停止），禁止誤回收。 執行 lgpu status 檢視活躍 Lease 與 PID，確認舊程序結束後將自動回收。
error_kind: "OOM" 取得 GPU Lease 後，在實際推論過程中發生顯存不足（如超高 DPI 超大圖）。 Lease 會自動回收且不留半成品；調低 --dpi（如 150）或改用 --allow-cpu-fallback 重試。

📊 RTX 4060 Laptop 實測基準與已知限制

🖥️ 實機測試平台

Windows 11 + NVIDIA GeForce RTX 4060 Laptop GPU (8188 MiB, Driver 621.14) + Python 3.12 隔離環境。

📈 實測顯存階梯

模型載入 +134 MiB → 首次推論 +956 MiB → 穩態峰值 +1,468 MiB；Manifest 保守申請 2,048 MiB。

🧪 測試驗證範圍

全倉 56 / 56 測試通過，含全倉 AST 掃描 0 處 shell=True、連續多輪 CUDA VRAM 歸還與故障注入驗證。

目前已知邊界與限制（M1 v1.0.0）：
  • 單卡範圍：M1 限定管理單一指定 NVIDIA CUDA GPU（透過 --device 0 指定）。
  • 模型精度透明揭露：RapidOCR 內建 PP-OCRv4 為 FP32 ONNX 模型，metadata.json 誠實標註為 fp32_onnx_cuda / fp32_onnx_cpu。
  • Windows 程序樹範圍：ocr_pdf 目前為單程序執行，不衍生孫程序；未來若有會衍生多層子程序的 Worker，將於 M2/M3 評估導入 Windows Job Object。
